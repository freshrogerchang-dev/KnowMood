# 認識情緒 KnowMood

給 **5–6 歲 ASD / ADHD 小朋友** 的情緒認知互動遊戲。
繁體中文、全語音朗讀、情緒名稱標注音，用平板就能玩。

> 技術：React 18 + Vite + Tailwind CSS，資料本機優先（localStorage），可選 Supabase 雲端同步。

---

## 為什麼這樣設計

這不是一般的兒童遊戲，每個決定都對應一個特教上的考量：

| 設計 | 原因 |
|---|---|
| **自己畫的 SVG 臉譜，不用 emoji** | emoji 在不同手機長得不一樣，孩子會把「情緒」和「某一張圖」綁在一起。自畫的臉可以刻意放大眉毛／眼睛／嘴巴三個關鍵線索。 |
| **無錯誤學習（errorless learning）** | 答錯不會失敗、不扣分、不換題，只把選項變淡；試兩次之後正確答案會輕輕浮動提示。孩子永遠會成功，不累積挫折。 |
| **沒有計時、沒有倒數** | 時間壓力會讓 ASD 孩子直接當機，也讓 ADHD 孩子更衝動作答。 |
| **一輪固定 4/6/8 題 + 進度點點** | 看得到「還剩幾題」，減少不確定感，做完就有明確的完成點。 |
| **選項數 2 → 3 → 4 漸進** | 從 2 選 1 開始，成功率高；穩定後家長再往上調。 |
| **低感官負荷模式** | 奶油底色、低飽和度色票、無閃爍；一鍵關掉所有動畫與音效。音效是 WebAudio 合成的柔和正弦音，有淡入淡出，沒有突兀的起音。 |
| **每個畫面左上角固定是「回家」** | 位置永遠不變，孩子建立得起操作預期。 |
| **所有按鈕至少 88×88px** | 幼兒精細動作還在發展，加上 `touch-action` 與停用長按選字，避免誤觸。唯一的例外是情緒溫度計在手機上的 5 個刻度（約 65×104px）—— 刻度必須並排才讀得出「愈右邊愈強」，而 5×88px 在手機寬度上放不下。臉的寬度改用卡片寬的百分比，任何螢幕寬度下大小遞增都還在。 |
| **表情模仿拆成眉毛／眼睛／嘴巴三步** | 「模仿一整張臉」對 ASD 孩子太抽象，拆成三個可執行的動作才做得到。 |
| **不開相機** | 表情模仿由大人長按確認，不拍照、不錄影，沒有任何影像離開裝置。 |
| **家長設定要長按 2 秒** | 擋住小朋友誤觸，又不用讓單手抱小孩的家長解數學題。 |

## 十一個模式

| 模式 | 內容 |
|---|---|
| 📚 **情緒圖鑑** | 8 種情緒的大臉譜 + 注音，四個分頁：**身體訊號**（怎麼看出來）、**我可以說**（情緒詞彙）、**我可以做**（因應策略）、**還可以這樣說**（詞彙家族，見下）。 |
| 🎯 **配對遊戲** | 偶數題「聽名字找表情」、奇數題「看表情找名字」，順序固定好預期。 |
| 🧩 **情境猜猜看** | 28 題生活情境（冰淇淋掉了、玩具被搶走、打雷⋯），練習從事件推論感受；答對後會說明「為什麼會有這種感覺」。 |
| 🔍 **情緒小偵探** | 情境猜猜看的進階版。16 個 2–3 句的短故事，先猜情緒，再判斷**強度 1–5 分**，最後攤開「你找到的線索」。強度沒有錯的答案（見下）。 |
| 🧍 **情緒在哪裡？** | 情緒圖鑑的延伸。從 6 張反應卡裡挑出屬於該情緒的動作（拍拍手／握緊拳頭／身體發抖⋯），挑錯會說「這個比較像是生氣的時候」；全部找到後顯示這個情緒**在身體的哪個位置**、是什麼感覺。 |
| 👂 **聲音裡的情緒** | 同一句中性的話（「這個給你」「換你了」），用不同語調唸出來，只靠**聲音**判斷心情。練的是語調辨識（prosody），見下。 |
| 👪 **真人表情** | 情緒圖鑑的延伸，練習把卡通臉譜學到的東西用在真人臉上（見下）。 |
| 🪞 **表情模仿** | 照著臉譜做表情，三步驟拆解，可以配鏡子或跟大人面對面。 |
| 📔 **今天的心情** | **事件 → 情緒 → 1–5 分強度** 三步驟。情緒溫度計用「臉愈大 = 感覺愈強」呈現，選完強度會提示更精準的說法（選填），4–5 分時會主動推薦去**冷靜角**（見下），記完會給對應的因應建議。可以看回顧。 |
| 🌿 **冷靜角** | 情緒工具箱：烏龜呼吸、吹泡泡、數到十、擠一擠。從主畫面進來就是單純的工具；從日記進來會記錄「做之前幾分、做之後幾分」，家長頁能看出**哪個方法對這個孩子真的有效**。 |
| 🎁 **我的貼紙簿** | 星星自動換 10 張貼紙，有進度條顯示「還差幾顆」。 |

### 情緒強度沒有標準答案

情緒小偵探的第二步要孩子給 1–5 分。故事有一個 `band`（大部分人會給的區間），
但**選在區間外不算錯、不扣分、不重來** —— 只會聽到「大部分的人會覺得幾分，因為……」。
落在區間內會多拿一顆星星。

情緒強度本來就因人而異，把孩子自己的感覺判定為「錯」會把整件事教壞；
但完全不給參考值，又學不到「同樣是難過，也有分大小」。這個設計是兩者的折衷。

### 情緒反應與身體感覺

`src/data/reactions.js` 為每個情緒定義了：

- `body` —— 這個情緒在身體的哪裡、什麼感覺（內感受 interoception），例如
  「害怕 → 心臟／肚子：心跳變得好快，肚子涼涼的，手心會流汗」
- `reactions` —— 4 個看得到、做得出來的動作（拍拍手、腳用力踩、抓緊大人的手⋯）

動作刻意寫成具體行為而不是抽象心理狀態，孩子才對得起來。
32 個動作在全部情緒裡都是唯一的，配對時不會出現兩個都對的情況。

ASD 孩子常常是「感覺到了但不知道那是什麼」，等情緒很大了才爆出來。
先學會辨認身體訊號與自己的反應，才有機會在情緒還小的時候就講出來。

### 聲音裡的情緒：語調辨識（prosody）

語調辨識是 ASD 很核心的困難之一——同一句話用不同語氣說，意思完全不同，
但這個線索常常接收不到。查過的同類 App 幾乎沒有做這塊。

句子刻意選「中性」的（「我要出去了」「這個給你」），光看字看不出心情，
只能靠 `speakWithTone()` 播出的語調判斷。Web Speech 只給 pitch / rate / volume
三個旋鈕，硬塞 8 種情緒會有好幾組聽起來幾乎一樣，所以只收了**六種聲音上真的分得出來**的
情緒（開心／難過／生氣／害怕／驚訝／累了），任兩組之間 pitch 或 rate 都至少差 0.25。
平靜與害羞沒有列進來——它們的聲音特徵（慢、小聲）跟難過、累了重疊太多，
連大人光聽都不容易分辨，那種題目只會讓孩子用猜的。

答錯不換題，會自動再唸一次；答對後說明「你是聽到什麼」（「聲音低低的、慢慢的」）。
語音關閉或瀏覽器不支援時會顯示原因，不會讓孩子看到壞掉的遊戲。

### 冷靜角：從「認出情緒」到「可以做什麼」

App 原本會提示「先深呼吸三次」，但沒有真的提供那個東西——孩子記錄了「生氣 5 分」，
按下確定，然後就結束了。冷靜角補上這一步，四個工具：

- 🐢 **烏龜呼吸**：吸 3 秒／停 1 秒／吐 4 秒，四輪
- 🫧 **吹泡泡**：慢慢吐氣把泡泡吹大，五輪
- 🔟 **數到十**：語音跟著一起數
- 🤏 **擠一擠**：要一直按著球才會前進，放開就停住等

全部用 JS 計時驅動、圓圈大小走 inline style，低感官負荷模式關掉 CSS transition 時
會變成一格一格跳，而不是整個動不了。

日記記到 4–5 分時會主動問「要不要先去冷靜角？」，把情緒與那筆日記的 id 帶過去；
做完再問一次「現在幾分」，寫回同一筆紀錄的 `calm_tool` / `after_intensity`。
家長頁會算出**每個工具平均降幾分、幾次有效**——深呼吸對某些孩子沒用、
擠壓卻有效，這種事只有資料看得出來。從主畫面直接進來則不留紀錄，
情緒上來的時候不該還要先填表。

### 真人表情：從卡通臉譜到真人臉孔

研究指出 ASD 孩子處理卡通臉和真人臉的策略不一樣——有些孩子不容易把卡通
當成真實事物的代表，這個落差不會自動類化過去，需要另外練習。

由家長在「家長設定 → 真人表情 → 管理家人表情相簿」拍下家人做出各種表情的照片
（可以加多個家人：爸爸、媽媽、哥哥⋯），遊戲會顯示一張真實照片，讓孩子從
熟悉的 SVG 臉譜卡片中選出對應的情緒——這個方向刻意設計成「真人 → 抽象符號」，
正好是研究指出的落差所在。

**隱私是這個功能唯一的紅線，做法上完全獨立於其他資料：**

- 照片存在裝置本機的 IndexedDB（`src/lib/familyPhotos.js`），跟 App 其他資料
  用的 localStorage / Supabase 同步邏輯完全分開的一個資料庫
- **沒有任何程式碼路徑會把照片送到 Supabase 或任何伺服器**——就算開了雲端同步，
  這裡的照片也不會被送出去（已用網路請求監聽驗證：整個上傳/遊玩流程零 Supabase 呼叫）
- 家人的暱稱也只存在本機（獨立的 localStorage key），不做雲端同步，避免牽連到照片
- 照片存之前會用 canvas 縮小到最長邊 480px、壓成 JPEG，避免相機原始照片佔用太多空間
- 刪除家人會把他所有情緒的照片一併從 IndexedDB 清掉

設定頁只藏在「家長設定」的長按閘門後面（家人拍照本來就該是大人決定的事）；
遊戲本身沒有照片時會顯示引導文字，請孩子去找大人設定，而不是提供繞過閘門的捷徑。

### 沒有照片時的示範畫面

還沒拍照片時，遊戲會提供「🎬 看示範怎麼玩」——借用「情緒圖鑑」已經做好的
插畫臉譜假裝是照片，讓家長不用等孩子先拍完照就能看到遊戲的操作流程。

刻意做了幾件事把它跟真正的練習分開：
- 虛線外框 + 明顯的「🎬 示範畫面・不是真的照片」標籤，跟真正的照片卡片
  （實線外框）一眼就能分辨
- **不算分**：不呼叫 addStars / recordAttempt，不會污染孩子真正的星星與紀錄
- 用中性的 tap 音效，不用 correct/star 音效，不會讓孩子誤以為在得分

這個示範本質上是卡通對卡通，教學價值上其實跟「配對遊戲」重複——
沒辦法真正示範「真人照片→抽象符號」這個轉換，純粹是給家長看操作流程用的。

（曾經考慮過用 AI 生成「假的」小朋友臉孔來源當示範內容，但沒有採用：
不論是不是虛構的孩童，生成擬真兒童臉孔本身就是不碰的紅線，
跟這個 App 的用途無關，是通用原則。）

### 情緒詞彙家族（39 個延伸詞）

每個核心情緒底下掛一串「同一家族、不同強度」的詞，目的是
**情緒細緻度（emotional granularity）** —— 能用愈精準的詞描述感受，情緒調節就愈容易。

```
開心   舒服 → 滿足 → 高興 / 得意 → 幸福 → 興奮
難過   失望 → 寂寞 → 委屈 → 傷心 / 想哭
生氣   不高興 → 煩躁 → 氣呼呼 → 火大 → 抓狂
害怕   緊張 / 擔心 / 不安 → 好害怕 → 嚇壞了
驚訝   好奇 → 意外 → 嚇一跳 → 驚喜 → 不敢相信
平靜   無聊 / 還好 → 放鬆 / 安心 → 自在
害羞   不好意思 → 怕生 / 尷尬 → 臉紅
累了   懶懶的 → 有點累 → 想睡 → 沒力氣
```

每個詞都標了**適用的 1–5 強度區間**和**什麼時候用**（例：「委屈 = 明明不是我的錯，
卻被說」）。ASD 孩子需要的是明確的使用規則，不是一串同義詞。

出現在兩個地方：

- **情緒圖鑑 →「還可以這樣說」**：由弱到強列出，左邊的長條顯示強度區間，點一下唸出詞 + 使用時機
- **今天的心情 → 強度步驟**：選完 1–5 分後，符合那個強度的詞會出現（最多 3 個），想選再選，
  不選也能存檔。選了就會存進紀錄，回顧顯示成「興奮（開心）」

**這些詞不會進入配對／情境遊戲的選項** —— 遊戲維持 4–8 個核心情緒，
才守得住「2 選 1 起步、無錯誤學習」的設計。孩子剛開始學時，
家長可以在設定頁把「情緒詞彙擴充」整個關掉。

情緒分三階解鎖：
1. **第一階**：開心、難過、生氣、害怕
2. **第二階**：＋驚訝、平靜
3. **第三階**：＋害羞、累了

## 快速開始

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 打包到 dist/，可直接丟 GitHub Pages / 任何靜態空間
npm run preview
```

打包用 `base: './'`，放在任何子路徑都能開（GitHub Pages 的 `/KnowMood/` 也沒問題）。

### 部署到 GitHub Pages

`.github/workflows/deploy.yml` 已經設好了：**推到預設分支就會自動打包並部署**，
也可以到 Actions 頁手動按 *Run workflow*。

第一次部署前：

1. repo → **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**
   （workflow 裡有 `enablement: true`，多數情況會自動開好，這步只是確認）
2. 要一併開雲端同步的話，到 **Settings → Secrets and variables → Actions → Variables**
   新增 `VITE_SUPABASE_URL` 與 `VITE_SUPABASE_ANON_KEY`。
   沒設也能部署，App 會退回「只存在裝置上」的離線模式。

網址會是 `https://<帳號>.github.io/KnowMood/`。用 iPad 開這個網址後
「加入主畫面」，之後不用開電腦也能玩。

### 平板使用建議

用 Safari / Chrome 開啟後選「加入主畫面」，就會全螢幕執行、沒有網址列。

## Supabase 雲端同步（選填）

**不設定也完全可以用** —— 所有資料都先寫進 localStorage，離線照玩。
設定之後，星星、貼紙、設定、心情日記、練習紀錄會自動同步，換裝置看得到同一份紀錄。

1. 複製環境變數：

   ```bash
   cp .env.example .env.local
   ```

   填入你的專案 URL 與 publishable / anon key。

2. 套用資料表（本專案的資料表已經建好了，新專案才需要）：

   ```bash
   supabase db push          # 或把 supabase/migrations/0001_knowmood_init.sql 貼到 SQL Editor 執行
   ```

### 資料表

| 表 | 內容 |
|---|---|
| `knowmood_state` | 星星、貼紙、設定、孩子暱稱（每個 `profile_id` 一列） |
| `knowmood_journal` | 心情日記：日期、事件、情緒、1–5 強度 |
| `knowmood_attempts` | 每一題的作答紀錄，給家長頁算正確率 |

同步策略是**本機優先**：每次操作先寫 localStorage，1.5 秒後才批次推到雲端；
開啟 App 時會先拉一次雲端資料合併（`state` 比 `updated_at`，日記與作答紀錄依 `id` 聯集）。
雲端連不上時 App 一切照常，家長頁會顯示「同步失敗」。

### ⚠️ 隱私提醒

為了讓孩子完全免登入，這三張表沿用這個 Supabase 專案既有的作法：
**RLS 有開，但政策對 anon 開放**，資料靠隨機產生的 `profile_id` 區分。
這代表拿到 anon key 的人理論上讀得到這幾張表的內容，所以：

- 暱稱請用小名，**不要填真實姓名**
- 事件描述**不要寫學校、班級、地址、他人姓名**
- 需要真正的資料隔離時，改用 Supabase Auth 匿名登入，把政策換成 `auth.uid() = user_id`

## 給家長 / 治療師

主畫面最下方 **長按 2 秒** 進入設定頁，可以：

- 調難度（情緒階段、選項數、一輪題數）
- 單獨關掉某些情緒（例如先不練「害怕」）
- 開關語音／語速／音效／動畫／注音／低感官負荷模式
- 看**每種情緒的一次答對率**、心情紀錄與平均強度
- **匯出 JSON**，帶去給老師或治療師看
- 清除所有紀錄

建議：**同一階段穩定到 80% 以上再往上調**。一次玩一輪（4–6 題）就好，見好就收。

```
src/
├── data/
│   ├── emotions.js      # 8 種情緒：注音、顏色、臉部參數、身體訊號、因應策略
│   ├── scenarios.js     # 28 題情境題庫
│   └── stickers.js      # 貼紙與所需星星數
├── lib/
```

## 視覺語言

- **不規則圓角**：卡片用 `28px 22px 29px 21px` 這種四角不等的圓角，相鄰卡片左右鏡像（`.blob-a` / `.blob-b`），看起來像手畫的而不是機器排的。
- **同色硬陰影**：陰影顏色跟卡片邊框同一色（`0 6px 0 var(--edge)`），按下去時位移 4px、陰影塌成 2px，給幼兒明確的「按到了」回饋。邊框色從呼叫端用 `--edge` CSS 變數傳進來。
- **紙張質感**：底色鋪 18px 網格、4.5% 透明度的圓點，大片奶油色才不會死板。
- **模式卡的幽靈表情**：每張模式卡右下角壓一個 28% 透明、旋轉 8° 的表情並裁切掉一半，六個模式用顏色 + 表情就能記住，不用先讀字。
- **標題字體**：`Yuanti TC`（iPad / Mac 內建的繁中圓體），不需下載字型檔；其他平台自動退回黑體。
- **遊戲選項卡刻意維持白底**：不用情緒色去染卡片背景，孩子才會去讀眉毛／眼睛／嘴巴，而不是用顏色抄捷徑。

## 離線使用（PWA）

App 是一個完整的 PWA：manifest + service worker（`vite-plugin-pwa`），
build 時把全部資源預先快取起來。「加到主畫面」之後**斷網也能開啟並正常遊玩**——
出門、坐車、網路不穩正好是最需要情緒工具的時候。

manifest 用相對路徑（`base`/`scope` 都是 `./`），GitHub Pages 的 `/KnowMood/`
子目錄一樣能正確註冊。圖示有 192 / 512 / maskable 三種，maskable 版留了
10% 安全邊距，避免 iOS/Android 裁圓角時切到臉。

## 語音朗讀的自然度

App 完全依賴 Web Speech API（免費、離線、零設定），這裡記錄怎麼在這個限制下
盡量讓聲音不那麼機械：

- **不做人工變調**：舊版每句話都疊加 `pitch = 1.05` 的統一數位變調，這種簡單的
  數位訊號處理反而會讓語音引擎原本設計好的音高（尤其 iOS/macOS 內建的類神經網路
  合成語音）多一層金屬感。現在一般朗讀維持 `pitch = 1`，用語音引擎原本的音高。
- **語音選擇改用加分制**（`scoreVoice()`）：優先 zh-TW，其次比對名稱裡的
  `Google`（Android/Chrome 上代表雲端合成，比內建 espeak 好很多）或
  `Enhanced/Premium/Natural/Neural/HD` 等廠商自標的高音質關鍵字。
- **家長設定頁會顯示目前用的是哪個語音**，並提供「🔊 試聽」按鈕；
  如果偵測到的語音不是高音質類型，會提示可以到系統設定安裝更好的中文語音包。
- 「聲音裡的情緒」遊戲用的 `speakWithTone()` 是刻意誇張的語調，維持不變——
  那個遊戲的目的正是要語調聽起來夠誇張、彼此夠好分辨。

**這個方法的天花板**：Web Speech 終究是裝置內建的語音引擎，音質上限就是
iOS/macOS 內建語音的水準（已經相當自然）或 Android 的 Google 雲端語音。
要再更進一步逼近真人錄音的水準，需要接雲端神經網路 TTS
（例如 ElevenLabs / Azure Neural TTS / Google Cloud TTS），但那會：
需要付費 API 金鑰、需要一個後端代理保護金鑰（不能把金鑰放進純前端的 GitHub Pages
專案）、而且需要連網（除非把固定的題目句子都預先合成音檔存下來，
才能維持現在「斷網也能玩」的 PWA 離線體驗）。這是可以做的下一步，
但涉及金費與架構決定，目前先把免費層級做到位。

## 已知的平台行為

iOS Safari 規定 `speechSynthesis` 的第一次發聲必須在使用者的觸控事件裡發生。
App 啟動時會掛一個 capture 階段的監聽，在第一次觸控時送出一個只有空白字元的
utterance 把語音引擎叫醒（不會出聲），之後整個 session 的朗讀就都正常。
因此在 iPad 上，開啟 App 後那句自動問候語仍然不會出聲 —— 這是 Safari 的限制，
但小朋友點下第一個按鈕之後，所有題目與情緒名稱都唸得出來。
